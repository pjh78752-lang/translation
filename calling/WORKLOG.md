# CALLING 한국어 패치 작업 인계

최종 정리: 2026-10-24 (한국 시간). 저장소: `pjh78752-lang/translation`.

## 다음 작업의 출발점

- 대상: Wii 일본판 **CALLING 검은 착신**, 게임 ID **SCAJ18**, Dolphin 사용자 플레이.
- 현재 최신 배포는 **0.0.5 설치 오류 수정본**이다. 초기 0.0.5나 0.0.4 ZIP 대신 아래 파일을 안내한다.
- ISO 도구: [Calling-Korean-v0.0.5-ISO-Kit-Installer-Fix.zip](https://github.com/pjh78752-lang/translation/raw/refs/heads/main/calling/Calling-Korean-v0.0.5-ISO-Kit-Installer-Fix.zip)
- 리소스 패치: [Calling-Korean-Partial-v0.0.5-Installer-Fix.zip](https://github.com/pjh78752-lang/translation/raw/refs/heads/main/calling/Calling-Korean-Partial-v0.0.5-Installer-Fix.zip)
- 설치 수정 커밋: `8fc3d52`. 제작 소스와 검사 기록: `source/v005/`.
- **수정본으로 사용자 PC에서 ISO 제작과 실행이 성공했다는 확인은 아직 없다.** 다음 결과를 이전 버전의 실행 확인과 혼동하지 않는다.

## 사용자에게 안내할 실행 방식

1. 최신 ZIP 전체를 새 폴더에 푼다.
2. `make-iso.cmd`를 실행한다. `wit.exe`를 직접 실행하는 방식이 아니다.
3. WIT 전체 폴더의 `wit.exe` → 보관한 **원본 일본판 ISO** → 별도 새 ISO 저장 위치 순서로 선택한다.
4. 구형 WIT에서 한글 경로 오류가 관찰됐다. WIT, 입력 ISO, 출력 위치는 `E:\Calling\original.iso` 같은 영문 경로를 쓴다. `wit.exe`만 따로 옮기지 않는다.
5. 원본을 보존하고 매 버전 원본에서 새 ISO를 만든다. 기존 한글 ISO에 패치를 겹쳐 적용하지 않는다. 완성된 ISO는 Dolphin에서 일반 실행한다.

사용자에게는 실제 GitHub 웹 다운로드 링크를 제공한다. `/workspace/...` 작업 경로 링크는 사용자가 다운로드하지 못했다. 업로드와 HTTP 응답/파일 해시 확인 뒤 링크를 안내한다.

## 겪은 오류와 해결

### ISO 형식 판별

`Select the original Japanese SCAJ18 Wii ISO`는 WIT 시작 오류가 아니라 입력 파일 헤더 확인 실패다. 원본 일본판 SCAJ18의 일반 ISO가 필요하다. RVZ 등은 Dolphin으로 ISO로 변환해야 하며 확장자만 바꾸면 안 된다.

### ConvertFrom-Json

초기 0.0.3의 UTF-8 JSON을 Windows PowerShell이 기본 한국어 인코딩으로 읽어 구문이 깨졌다. 두 스크립트의 `Get-Content`에 `-Encoding UTF8`을 명시하고 manifest는 ASCII 이스케이프 JSON으로 저장했다. 최신 배포에도 유지된다.

### WIT ERROR #76: CAN'T OPEN FILE

한글이 들어간 입력 경로에서 발생했다. 영문 경로로 안내한 뒤 사용자가 보낸 다음 로그에서는 실제 ISO 추출이 성공했다. WIT는 사용자 환경에서 `3.04a r8427 cygwin64`였다.

### IPS record is out of bounds

사용자는 초기 0.0.5에서 1/5 추출을 완료하고 2/5 패치 단계에서 실패했다. 원인은 합성 IPS에 남은 과거 쓰기 기록이다. 대사 파일이 작아졌는데 예전 기록이 최종 크기를 넘었다. Python 적용기는 마지막에 잘라냈지만 PowerShell 설치기는 최종 크기만 할당하여 거부했다.

최신 수정에서는 `normalize_ips`로 겹친 기록을 최종 쓰기 값으로 합치고 최종 파일 범위 밖 기록을 제거한다. 설치기의 범위 검사나 원본 해시 검사를 완화하지 않는다. 적용 후 파일의 크기와 SHA-256, 번역 내용은 초기 0.0.5와 동일하다. `source/v004/build_v004.py`와 `source/v005/build_v005.py`의 합성 코드도 수정했다. 과거 ZIP은 기록용으로 남아 있고, 최신 수정본은 별도 파일명이다.

## 검증의 범위

확인한 항목:

- 모든 2,516개 슬롯, 이전 번역, 제어 문자, `<X>`/`<N>` 형식 지정자 보존.
- 문서의 전화번호·퍼즐 숫자 블록·가림 표시 보존.
- 기존 글리프 픽셀/매핑과 새 문자 지원, 압축 왕복, IPS 합성, ZIP/XML/설치 경로.
- IPS 범위 초과 재현/겹침/미변경 입력 보존/반복 정규화 회귀 검사 4개.
- 수정 패치의 모든 쓰기가 최종 크기 이내이고 출력 해시가 기존 0.0.5와 동일함.
- **Linux PowerShell 7.5.4**에서 실제 `install.ps1`의 시험 입력 적용, 출력 리소스 3개 해시 일치, 같은 출력으로 재실행.
- 배포 manifest의 원본 해시 검사를 유지했고, 이미 패치된 입력을 실제로 거부함.
- 최신 ISO 수정 ZIP의 GitHub HTTP 200 응답과 로컬 파일 SHA-256 일치.

PowerShell 시험은 제공된 **0.0.2 적용본**을 사용했다. 별도의 시험 manifest에서만 입력 해시를 그 파일에 맞췄다. 배포본의 원본 일본판 해시는 바꾸지 않았다. 이 시험을 원본 리소스 대상 설치나 전체 ISO 제작 검증이라고 부르지 않는다.

미검증: Windows PowerShell 5.1 실제 실행, 전체 원본 ISO 재생성, 최신 버전의 Dolphin 플레이와 줄바꿈/화면 배치, 다른 이미지/리소스의 번역 누락. 예전 0.0.2 ISO는 사용자가 실행된다고 보고했지만 최신 수정본의 확인과는 별개다.

## 재빌드와 다음 수정

- `source/v005/build_v005.py`: Python 3 + Pillow + NotoSansCJK-Regular.ttc.
- 입력: **0.0.4 ISO 도구 ZIP** 및 **0.0.2 또는 0.0.4 적용본 리소스 3개**. 0.0.2 입력은 해시 확인 뒤 메모리에서 0.0.4 기준으로 올린다. 사용자 원본은 덮어쓰지 않는다.
- 리소스 이름: `font.bin`, `win_mess_jp_jp.bin`, `SubTitle.bin`.
- 배포 `install.cmd`/ISO 도구의 입력은 이 빌더와 달리 **원본 일본판**이다.
- 새 환경에서 과거 첨부 파일이나 `/workspace/calling-dev` 등이 남아 있다고 가정하지 않는다. 사용 가능한 파일을 먼저 찾고 해시/버전을 확인한다. 원본 ISO 전체 업로드가 필요하다고 먼저 요청하지 않는다.
- 다음 스크린샷에서 일본어가 보이면 최신 ISO 사용 여부와 해당 문구가 이 텍스트인지 다른 이미지/리소스인지 확인한다. 이 파일의 문장이 남아 있지 않다는 검사만으로 게임 전체의 완역을 단정하지 않는다.
- 테스트: `python calling/source/v005/test_ips_bounds.py`.
- 상세 기록: `source/v005/validation.json`, `source/v005/installer-validation.json`.
